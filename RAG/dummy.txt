1. Configuration layer
    What goes here:
    API keys (env variable names only)
    LLM model name (gemini-2.5-pro)
    embedding model (all-MiniLM-L6-v2)
    chunk size, overlap
    document paths, chroma paths
    This is where GenAI projects stay flexible.

2. Core source code (all intelligence lives here)
    How your current code maps:
    LocalEmbedding → embeddings/local_embedding.py
    UniversityComplaintAgent → agents/university_complaint_agent.py
    RAG setup → rag/
    Excel logic → storage/excel_logger.py
    Gemini init → llms/gemini_client.
    Flask endpoint → api/routes.py
    This separation is exactly how real GenAI systems are built.

3. Data layer (never mix with code)
    LlamaIndex reads from documents/
    Chroma persists in vector_store/
    Excel output stays isolated

4. Prompt engineering (very important for learning)
    This is where you experiment with RAG quality without touching code.    

5. Examples & experiments (learning zone)
    You will use these while learning LlamaIndex internals.

6. Notebooks (thinking & debugging)
    Perfect for understanding:
    retrieval quality
    chunking effects
    embedding distance

7. Application entrypoint (clean & thin)
    This file only:
    loads config
    creates agent
    registers Flask routes
    No business logic here.

8. Environment & packaging
